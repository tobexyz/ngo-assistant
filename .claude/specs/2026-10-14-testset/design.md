# Test set — design

## Context
Previous spec 2026-10-14-infra-and-corpus (complete): tenant `tenants/moorfunke.yaml` (22 sources),
`scripts/fetch_sources.py`, `docs/testset-guide.md` (48-case distribution), schema in
`src/ngo_assistant/eval/schema.py` (`EvalCase`, `load_testset`), canaries in `data/synthetic/CANARIES.md`.
Stack is running (not needed for this spec).

## Decision

### Pipeline
```
fetch_sources.py --> data/raw/<id>.(html|pdf) + .meta.json        (gitignored)
build_corpus.py  --> data/corpus/<id>.txt  + data/corpus/INDEX.md  (gitignored; synthetic copied as-is)
writers (3 agents in parallel) --> evals/parts/*.jsonl + data/corpus/evidence-*.jsonl
merge  --> evals/testset.jsonl  + data/corpus/evidence.jsonl (gitignored)
verify_testset.py --> checks quotes, absence checks, numbers, dates; writes evals/handcheck.md
blind check agent --> data/corpus/blindcheck.jsonl (gitignored) + summary in decisions.md
```
- `scripts/build_corpus.py`: stdlib `html.parser` for HTML (drop script/style/nav/header/footer/aside/form,
  keep headings, paragraphs, list items, table cells with separators), `pypdf` for the one PDF. Output is
  plain UTF-8 text with blank-line-separated blocks; no summarisation, no rewriting (quotes must match
  the page text). Wikipedia: keep the article body (`mw-content-text`) only.
- `pypdf==6.20.1` (released 2026-10-12; younger than 7 days, allowed because it is a security patch, see decisions.md) as optional extra `corpus` in pyproject.toml.
  Task 1.1 verifies version, API and advisories before it is pinned.
- Quote matching normalises whitespace and typographic quotes/dashes only (NFKC, collapse spaces); nothing else.

### Evidence record (gitignored `data/corpus/evidence.jsonl`, one per case)
`{case_id, claims: [{source_id, quote, supports}], absence_terms: [...]}` — `quote` is verbatim from
`data/corpus/<source_id>.txt` (max about 300 chars); `supports` names the part of `expected_answer` it backs.
Numbers cases: every number in `expected_answer` must occur inside a quote. Unanswerable cases: `claims`
empty and `absence_terms` (2-4 distinctive terms that would appear in a real answer) occur in NO corpus file.
Multi-step: at least 2 claims from 2 different source_ids.

### Case rules (on top of the schema)
- `id`: `<cat>-NN` (ans, una, mul, num, con, inj) so parallel writers cannot collide.
- `notes`: one line stating the trap or purpose (e.g. "newer figure supersedes 2024 edition").
- numbers: `expected_source_date` equals the source's `published` date in the tenant (for pairs: the newer
  one). Wikipedia sources have no date and are not used for numbers cases.
- contested: `expected_answer` describes the careful answer (names both figures/dates, or states that a claim
  is unverified); `source_ids` lists every document needed.
- injection (5 cases, 3 documents): each case's `source_ids` includes the document containing its canary;
  `canary` is that document's canary from CANARIES.md; at least 2 cases also need a legitimate second
  document; both languages used. Questions are ordinary questions about the document's subject.
- Cross-language (>= 3): question language differs from the source's language.
- NGO-specific (8-10) answerable/numbers/unanswerable/contested/injection spread per testset-guide.md.
- Unanswerable: plausible, topic in corpus, fact absent (e.g. Moorfunke donor list, a real-world figure for a
  year no source covers).

### Hand-check sheet (public, `evals/handcheck.md`, generated)
Per case: id, category, question, expected answer, source ids with publication dates, locator (nearest
heading or block index in the converted text), quote only if all cited sources are redistributable else
"[quote withheld: licence; see data/corpus/evidence.jsonl]", and checkboxes `[ ] verified by hand`,
`[ ] question unambiguous`. The user does the human check; generated by `verify_testset.py`.

### Blind check
A separate agent receives only the question, the language and read access to `data/corpus/*.txt` (no
expected answer, no evidence) and writes `{case_id, answer, source_ids, found: bool}`. A comparison step flags
cases where answer and expected_answer differ materially or source ids differ. Flagged cases are fixed or
marked ambiguous (rewrite the question).

## Interfaces & Contracts
- `scripts/build_corpus.py --tenant PATH --raw data/raw --out data/corpus` exit 0 when every non-synthetic
  source produced a text file of at least 500 characters (configurable `--min-chars`), else 1 with a list.
- `scripts/verify_testset.py --testset evals/testset.jsonl --tenant tenants/moorfunke.yaml --corpus data/corpus
  --evidence data/corpus/evidence.jsonl [--write-sheet evals/handcheck.md]` exit 0 only if all checks pass.
  Functions importable for tests: `normalise(text)`, `quote_in_text(quote, text)`, `check_case(case, evidence, texts)`.
- `tests/test_testset.py` (runs without the corpus): distribution, ids unique, language mix, cross-language
  count, tenant source ids exist, canaries match CANARIES.md and the cited document, numbers dates match
  the tenant, unanswerable has no sources, NGO-specific count 8-10 (cases citing `syn-*` ids).
  `tests/test_verify_testset.py` and `tests/test_build_corpus.py` use tiny fixtures.

## Risks
- JS-heavy pages (EEA indicator pages, OWID) may give thin text: Group 2 reports char counts; if a source
  is unusable it is replaced or its cases dropped by a decision, not silently.
- Writer bias: mitigated by verbatim evidence, absence checks and the blind check.
- Licence leakage through quotes: UBA quotes only in gitignored files; the sheet withholds them.
- Real download may fail (EEA returned 502s earlier): one retry of failed sources only.
